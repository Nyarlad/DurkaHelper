# Политика безопасности

[English](SECURITY.md) | Русский

Используйте DurkaHelper только для разрешённого защитного review и инфраструктуры соревнований. Считайте деревья исходников, конфигурацию и отчёты недоверенными и чувствительными входными данными. Ядро не исполняет сканируемые исходники, не применяет патчи автоматически и не запускает эксплуатацию уязвимостей.

<a id="reporting-a-security-issue"></a>
## Как сообщить о проблеме безопасности

**Не публикуйте** учётные данные, приватные адреса, реальные захваты трафика или неочищенный эксплойт против настоящего сервиса в публичном issue.

Проверенный приватный канал сообщений — **условие публикации**. Прежде чем открыть репозиторий, сопровождающий должен включить и проверить GitHub private vulnerability reporting либо описать здесь другой согласованный приватный канал. Этот репозиторий не утверждает, что приватные сообщения уже включены, и не указывает непроверенный email.

Если на странице Security в GitHub есть **Report a vulnerability**, перед отправкой убедитесь, что кнопка открывает приватную форму. Иначе запросите приватный контакт через публичный issue без содержательных подробностей; не включайте чувствительные данные до подтверждения канала.

Укажите затронутый commit, платформу, минимальное синтетическое воспроизведение, ожидаемое и наблюдаемое поведение, а также последствия. Удалите секреты из имён файлов, вывода и вложений.

<a id="supported-security-boundary"></a>
## Поддерживаемая граница безопасности

Поддерживается только текущая сопровождаемая ревизия; перенос исправлений на старые закреплённые версии toolchain не обещается. У внешних интеграций сохраняются собственные upstream-политики и лицензии. Закрепление версии повышает воспроизводимость, но не обеспечивает постоянное устранение уязвимостей.

Особенно важно сообщать об исполнении исходников, раскрытии секретов, path traversal, обходе защиты от symlink/race, небезопасном восстановлении или перезаписи, обходе сравнения scope, непреднамеренном создании Docker-ресурсов и false negatives проверки публикации. Чистый статический scan или поиск секретов не доказывает безопасность.
