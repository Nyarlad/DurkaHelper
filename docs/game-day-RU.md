# Runbook игрового дня

[English](game-day.md) | Русский

Это краткое руководство по работе после успешной [репетиции развёртывания](MACOS_FULL_DEPLOYMENT_AND_TESTING-RU.md). Соблюдайте область разрешений организаторов и назначайте одного ответственного за deployment каждого сервиса.

<a id="receive-a-service"></a>
## Получение сервиса

Найдите настоящие пути его исходников, запуска, конфигурации и данных, а также неизменяемую ревизию. Держите проекты игровых сервисов отдельно от проектов командных S4DFarm/Neo/Packmate.

Свидетельство: `REVIEWED`; эффект `READ-ONLY`; рабочий каталог — фактический Compose-каталог разрешённого сервиса. Требование: правильный daemon/project и согласованный доступ. Ожидается: список и состояние сервисов только этого проекта; локальный вывод может раскрывать пути. Rollback: не нужен.

```bash
pwd
docker compose config --services
docker compose ps -a
```

Если при deployment используются явные параметры project/file, используйте те же самые параметры. Не печатайте expanded configuration. Выполните один обычный пользовательский сценарий и сохраните разрешённый образец старых данных. Затем создайте ограниченный baseline и scan исходников.

<a id="availability-failure"></a>
## Сбой доступности

Сохраните время сбоя и последнее изменение. Изучайте только состояние затронутого проекта, здоровье зависимостей и ограниченные приватные логи; логи могут содержать секреты и должны оставаться вне публичного экспорта evidence. На общих системах избегайте общих списков всех контейнеров и процессов хоста.

| Симптом | Следующая проверка |
|---|---|
| Компонент остановлен или перезапускается | Причина выхода, параметры запуска, готовность зависимостей |
| UI работает, но действия не проходят | База данных, persistence, точный API и аутентификация |
| На хосте работает, teammate не подключается | Ethernet-адрес, опубликованный порт, политика хоста, путь клиента |
| Сбой начался после патча | Точный diff и отрепетированный rollback кода/образа |
| Health проходит, checker падает | Настоящая семантика checker, обычный сценарий и старые данные |
| Очередь не движется | Согласованный протокол, лимиты, ответ receiver и состояние submission |
| Neo не подключается | Правильная версия клиента, адрес/key coordinator и доступность farm |
| Packmate не показывает streams | Видимость источника, режим, регистрация сервиса и временное окно |

Перезапуск не восстанавливает потерянные данные. Не используйте down -v, не удаляйте volumes и не меняйте сеть на основании подозрения. Перед перезапуском разберитесь с сохранением данных.

<a id="suspicious-traffic"></a>
## Подозрительный трафик

Используйте согласованную точку наблюдения и короткий временной интервал. Сравните request/response, method/path, типы параметров, size/status и события приложения с нормальным поведением. Сохраняйте только необходимые приватные свидетельства.

Общая LAN не означает видимость пакетов. UI Packmate без известного request/response не подтверждает рабочий захват. Импорт FILE — запасной вариант, а не доказательство непрерывного LIVE-анализа.

<a id="patch-loop"></a>
## Цикл патча

[Review кода](code-review-RU.md) → [рецепт каталога](vulnerabilities/README-RU.md) → [regression/deployment/rollback](patch-validation-RU.md). Сохраняйте нормальное поведение и текущие данные; не удаляйте нужную функцию только ради исчезновения сигнала.

Для явно заданных health checks приватно адаптируйте [services.example.json](../config/services.example.json); никогда не вставляйте пароли в URL. Свидетельство: `REVIEWED`; эффект `READ-ONLY` GETs; рабочий каталог — корень; ожидается true для всех настроенных проверок.

```bash
python3 scripts/http_probe.py local/services.json --timeout 2 --workers 2
```

Это проверяет настроенное HTTP-поведение, а не Neo gRPC, полноценный вход или семантику игрового checker. Форматы и ограничения описаны в [локальных инструментах](local-tools-RU.md). При сбоях общей инфраструктуры используйте [шпаргалку администратора](TEAM_LAN_ADMIN_CHEATSHEET-RU.md).
