# Установка и работа командных инструментов на macOS

[English](MACOS_FULL_DEPLOYMENT_AND_TESTING.md) | Русский

Маршрут админа: от клонирования до работающего командного стека. Участникам нужна [инструкция участника](participant-guide-RU.md). Все команды ниже выполняются из корня репозитория DurkaHelper.

Первое развёртывание выполняйте по короткой [first-run инструкции](MACOS_FIRST_RUN-RU.md), начиная с read-only `python3 durka.py doctor`. Полное руководство — справочник настроек/recovery, а не доказательство пройденной репетиции на реальном Mac.

<a id="1-know-the-layout"></a>
## 1. Как устроено

DurkaHelper запускается нативно в Python. Docker Desktop поднимает S4DFarm, координатор/worker Neo и Packmate FILE. Защищаемые сервисы остаются на Vulnbox в Ethernet-сети. Ноутбук обслуживает инструменты, а не развёртывание защищаемых сервисов.

Ферма = флаги и отправка. Neo = распределение/исполнение скриптов. Packmate = анализ трафика. Сканер = разбор локальных исходников. [Схема связей](team-setup-RU.md).

<a id="2-install-prerequisites"></a>
## 2. Установить необходимое

Установите Git, Python 3.10+ и Docker Desktop разрешённым для вашей машины способом. Запустите Docker Desktop и проверьте:

```bash
uname -m
python3 --version
git --version
docker version
docker compose version
```

Apple Silicon должен показать `arm64`. Закреплённый образ Packmate существует только для amd64, поэтому используется эмуляция Docker Desktop. Начальный бюджет — 4 CPU, 8 GiB RAM и 96 GiB диска Docker; уточните его по своей нагрузке. Оставьте место на диске хоста для PCAP и backup.


<a id="3-clone-and-configure"></a>
## 3. Клонировать и заполнить конфиг

```bash
git clone https://github.com/Nyarlad/DurkaHelper.git
cd DurkaHelper
python3 durka.py init
```

Откройте `local/durka.json` в редакторе. Пароли/ключ уже сгенерированы. Измените:

| Настройка | Что указать |
|---|---|
| `profile.bind_address` | Ethernet IPv4 для доступа команды; `127.0.0.1` оставьте только для прогона на одном ноутбуке |
| `profile.ports` | По умолчанию ферма 8080, Neo 5005, Packmate 65000; меняйте, если порт занят |
| `profile.farm.teams` | Названия команд и реальные адреса сервисов/Vulnbox |
| `profile.farm.flag_format` | Regex флага от организаторов |
| `profile.farm.protocol_settings` | URL/token отправки соревнования |
| `profile.farm.submit_limit / submit_period / flag_lifetime` | Лимиты и время соревнования |
| `profile.packmate.local_ip` | IP стороны сервиса, представленный в PCAP |
| `credentials` | Сгенерированные пароль фермы, ключ Neo и логин/пароль Packmate; выдавайте только нужное |

Для native workers участников нужен настоящий Ethernet bind: координатор передаёт им LAN URL фермы. Loopback-демо поддерживает внутренний маршрут фермы только для встроенного worker.

Текущий адаптер — `ructf_http`. Для другого протокола не включайте отправку, пока не будет совместимого адаптера. Инструменты и просмотр трафика можно запустить с выключенной отправкой.

В `local/` лежат приватный конфиг, скачанные исходники, данные стека и captures. Не показывайте его в Git. Для домашнего прогона настройки отправки могут оставаться примерами, пока сама отправка выключена.

На соревновании остановите стек, отредактируйте LAN/команды/отправку/Packmate, примените конфигурацию и запустите снова. Данные/образы сохраняются; скачивания и пересборка не нужны:

```bash
python3 durka.py down
python3 durka.py configure
python3 durka.py up
```

Редактируйте `local/durka.json` между `down` и `configure`. Замена платформы или credentials — отдельная подготовка.

<a id="4-prepare-while-internet-is-available"></a>
## 4. Подготовить при доступном Интернете

```bash
python3 durka.py setup
```

Команда получает закреплённые версии исходников/образов, готовит приватный workspace и собирает ферму/Neo. Это может занять несколько минут. Проверки версий и образов выполняются автоматически; переписывать checksum руками не нужно.

Выполняйте подготовку на машине, с которой будете работать. Linux amd64-кеш не содержит нативные зависимости Mac и не подтверждает скорость Apple Silicon. До отключения сохраните Docker Desktop, Python, репозиторий, образы, клиент Neo и нужные скрипты/зависимости.

<a id="5-start-and-check-access"></a>
## 5. Поднять и проверить доступ

```bash
python3 durka.py up
python3 durka.py status
```

Запуск включает UI/API фермы, координатор Neo и UI Packmate. Создаётся пустой PCAP, поэтому интерфейс работает до первого capture. Отправка флагов и worker пока выключены.

Откройте URL фермы и Packmate из `status`; войдите с данными приватного конфига. Затем откройте те же LAN-адреса с другой физической машины. `localhost` у участника указывает на его машину, а не на ваш ноутбук.

Передайте участникам только нужные URL/пароль фермы, URL/логин Packmate и адрес/ключ Neo. Database/Redis/Docker не раздаются команде. Если macOS запросит входящие соединения, разрешите нужное приложение в рамках своей политики; не отключайте firewall.

<a id="6-traffic-and-scripts"></a>
## 6. Трафик и скрипты

Для первого маршрута на Mac получите закрытый разрешённый PCAP и импортируйте:

```bash
python3 durka.py traffic import /path/to/closed-capture.pcap
```

Откройте Packmate, зарегистрируйте сервис и шаблон поиска, затем один раз начните обработку. Найдите известные запрос и ответ. Для следующих файлов используйте ту же команду импорта. Она заменяет активный файл, сохраняя предыдущий. Все варианты, Linux/Vulnbox LIVE и ограниченный ручной захват — в [работе с трафиком](traffic-capture-RU.md).

Для исполнения командных скриптов установите совместимый клиент Neo v2.4.2 авторам скриптов и следуйте [Neo](neo-RU.md). Когда скрипты готовы, запустите worker админа:

```bash
python3 durka.py worker
```

Встроенный light-worker содержит shell, но не полный Python/Sage. До использования подготовьте совместимые workers с реальными зависимостями скриптов. Им нужны маршруты до координатора, фермы и разрешённых сервисов-целей.

<a id="7-enable-submission-and-defend"></a>
## 7. Включить отправку и защищать

После проверки реального адаптера, endpoint, формата флага и списка команд:

```bash
python3 durka.py submit
```

Смотрите accepted/rejected/expired в ферме. Доступный UI ещё не означает принятие флагов соревнованием.

Для каждого сервиса скопируйте исходники с Vulnbox в приватный рабочий каталог и запустите скан:

```bash
python3 durka.py scan /path/to/service --patches
```

Прочитайте связанную инструкцию, сохраните оригинал, примените небольшой патч на Vulnbox и проверьте доступность/checker. Повторите скан исходников. Сканер читает файлы; по SSH в цели не заходит, код не запускает и фиксы не развёртывает.

<a id="8-rehearse-offline-and-with-load"></a>
## 8. Прогнать офлайн и под нагрузкой

Дома используйте Mac и отдельный ПК в проводной LAN: войдите в ферму/Packmate, подключите Neo, импортируйте известный трафик, выполните безвредный скрипт и переподключитесь после перезапуска своего приложения. Затем отключите Интернет, сохранив LAN, и повторите запуск/работу.

Проверьте инструменты под обычной нагрузкой не менее 60 минут. Следите за памятью/CPU Docker, ростом PCAP/БД и свободным диском. На событии повторите проверку доступа каждого устройства и выберите подготовленный разрешённый источник трафика.

<a id="9-backup-stop-and-recover"></a>
## 9. Backup, остановка и восстановление

`down` останавливает deployment и сохраняет данные/образы. Это не backup. Перед рискованным патчем сохраните оригинальные файлы сервиса и используйте native dump его БД.

Для общего FILE-стека [native backup и recovery](../deployment/README-RU.md#native-backup-and-quarantine-restore) используют dumps и новый изолированный restore. Backup намеренно останавливает запись в исходный стек. Recovery очищает Redis-очереди/кеш/сессии нового кандидата, чтобы не переотправить старую работу; используйте процедуру, только если эта потеря приемлема.

```bash
python3 durka.py down
```

Сначала остановите задания/захват, затем стек. Для обычного shutdown не используйте `docker compose down -v` или общий `docker system prune`.

<a id="10-common-problems"></a>
## 10. Частые проблемы

| Симптом | Следующий шаг |
|---|---|
| Docker недоступен | Запустить Docker Desktop, дождаться Engine, повторить `status` |
| UI работает локально, с ПК нет | Проверить Ethernet bind/IP, точный URL/порт, политику входящих соединений macOS и разрешённый LAN-путь |
| Флаги есть, отправки нет | Включить её только после проверки адаптера, URL/token и expiry |
| Задание Neo падает | Наличие worker, интерпретатор/зависимости и маршруты до цели |
| Packmate пустой | IP сервиса, регистрация сервиса/шаблона, закрытый capture и известный трафик |
| Apple Silicon тормозит | Эмуляция и ресурсы Docker; уменьшить capture/нагрузку или использовать разрешённый Linux-узел |
| Заканчивается диск | Остановить новый захват/импорт, сохранить нужное и удалить только определённые старые приватные файлы |

Для удаления выполните `down`, сохраните нужные backups, затем удалите только свой остановленный deployment/source/data из `local/`. Удаление Docker Desktop и общих образов — отдельная задача администрирования машины.
