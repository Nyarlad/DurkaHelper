# Краткая шпаргалка защитника

[English](defense-cheatsheet.md) | Русский

Перед изменением уточните разрешённый сервис, порядок запуска/пути данных, checker и ответственного за rollback. Сохраните предыдущие код/образ и подходящий backup. Карточка и ручное переписывание hashes не требуются.

| Ситуация | Действие |
|---|---|
| Первый доступ | Обычный пользовательский сценарий, образец старых данных, inventory/baseline, scan исходников |
| Сигнал сканера | Откройте точную ссылку каталога; проследите ввод → проверка → опасная операция |
| Подозрительный запрос | Сравните с нормальным трафиком в коротком временном окне; не публикуйте raw evidence |
| Предложен патч | Один падающий regression test, минимальное изменение, проверки своего/чужого/анонимного пользователя и старых данных |
| Deployment | Один ответственный, точный собственный сервис, сохранённый предыдущий образ/код и актуальные данные |
| Регрессия доступности | Сохраните причину; выполните отрепетированный rollback кода, не перезаписывайте новые раунды старой БД |
| Нет трафика | Проверьте разрешённую точку захвата; общая LAN не означает видимость пакетов |
| Неясный результат | Partial/blocked, никогда не ложное «чисто» |

[Сканер](offline-scanner-RU.md) · [Рецепты по языкам](vulnerabilities/README-RU.md) · [Чеклист патча](patch-validation-RU.md) · [Игровой день](game-day-RU.md) · [Шпаргалка администратора](TEAM_LAN_ADMIN_CHEATSHEET-RU.md)

Никогда не используйте общий prune, down -v, непроверенную ротацию учётных данных, широкие изменения firewall или произвольное исполнение исходников как быстрый обход проблемы. Согласованные изменения состояния требуют rollback. Игровые checkers важнее удобного зелёного /health endpoint.
