# Чеклист релиза и публикации

[English](release-checklist.md) | Русский

Чеклист сопровождающего, а не форма оператора. Для развёртывания используйте [инструкцию Mac](MACOS_FULL_DEPLOYMENT_AND_TESTING-RU.md). Готовность к публикации и к соревнованию учитываются отдельно.

<a id="source-and-tests"></a>
## Исходники и тесты

- [ ] Одобренный source commit и чистое tracked tree; без посторонних изменений.
- [ ] Полный unit suite и coverage ledger проходят, включая docs links/anchors, английский текст и соответствие парных русских переводов; команды и примеры остаются идентичными.
- [ ] Новые и изменённые правила соответствуют независимому positive/negative coverage языков.
- [ ] Точно распакованный core bundle проходит; archive manifest/checksums проверены.
- [ ] Внешние kits проходят строгий verifier; частичный экспорт образов не выдаётся за полный toolchain. Релиз только core не заявляет наличие сторонних runtimes.
- [ ] Результаты Linux integration и macOS ARM64 CI относятся к явно указанным commits.
- [ ] Заявленная поддержка соответствует текущей странице возможностей; generated outputs остаются вне Git.

<a id="publication-safety"></a>
## Безопасность публикации

Запускайте из корня репозитория. Эти read-only проверки показывают категории и расположения, а не найденные значения секретов.

```bash
python3 scripts/publication_check.py --root . --allowlist config/publication-allowlist.json
python3 scripts/publication_check.py --root . --history --ref HEAD \
  --allowlist config/publication-allowlist.json
```

- [ ] Проверьте каждый ref, предназначенный для публикации, а не только HEAD; checker принимает повторяющиеся явные --ref arguments.
- [ ] При необходимости используйте игнорируемый приватный denylist для строк локальных endpoints/identities; никогда не коммитьте его.
- [ ] Отдельно проверьте candidate archives, screenshots, CI artifacts и PR material. Проверка текста/истории не является OCR скриншотов и не доказывает безопасность удалённых артефактов.
- [ ] Нет keys/tokens, заполненных profiles, raw logs/PCAP, игровых данных, личных путей или описания частного deployment оператора.
- [ ] Синтетические исключения точны, узки и обоснованы; никогда не исключайте целиком tests/docs.
- [ ] Сохраняйте законное авторство, citations и license attribution.
- [ ] Подтвердите работающий приватный канал сообщений об уязвимостях согласно [SECURITY](../SECURITY-RU.md).
- [ ] Правомерность распространения сторонних binaries/images проверена; иначе распространяйте только core.
- [ ] Заявления version/changelog/support соответствуют точному релизу.

Изменение видимости репозитория, удаление refs, переписывание истории или публикация сторонних артефактов — отдельные осознанные действия. Не автоматизируйте их как косметическую уборку.

<a id="release-candidate-and-public-access"></a>
## Релиз-кандидат и публичный доступ

`RELEASE_CANDIDATE_READY` означает фиксированный source commit и core-архив, прошедшие применимые релизные проверки, с указанными оставшимися platform/event gates. Это не означает публичность репозитория или сертификацию игровой среды.

`PUBLIC_RELEASE_VERIFIED` дополнительно требует явного разрешения владельца на публикацию и успешного анонимного доступа к выбранному репозиторию, README, workflow оператора и скачиванию исходников. До разрешения проверьте все открываемые ветки/историю, PR material и CI assets; сохраните законную историю и тестовые fixtures. Нельзя молча удалять исторические материалы или переписывать commits ради зелёной проверки.

Если правила соревнования требуют публичность, это обязательное условие до игры. Приватный release candidate его не закрывает. [Workflow администратора](ADMIN_WORKFLOWS-RU.md) — рабочий маршрут; локальные результаты проверок остаются приватными.

<a id="competition-gate"></a>
## Условия готовности к соревнованию

- [ ] Проверены архитектура реального целевого Mac, точные версии OS/Desktop и ресурсный бюджет.
- [ ] Отрепетированы functional paths farm/coordinator/worker/Packmate и native recovery.
- [ ] Нет нерешённого P0 failure, partial result или непринятого blocker.
- [ ] Полный offline cold start проходит без скрытых downloads.
- [ ] Каждое физическое устройство teammate проходит полезные сценарии с аутентификацией и reconnect.
- [ ] Разрешённый непрерывный capture видит известный двусторонний трафик при ограниченном storage.
- [ ] Не менее 60 минут совместной нагрузки toolchain; в источнике захвата нет секретов.
- [ ] Новый оператор может пройти английское руководство без AI.
