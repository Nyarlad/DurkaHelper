<a id="prepare-the-machine-once"></a>
## Подготовьте машину заранее

Сканеру нужен Python 3.10+; полному стеку — ещё Docker и кешированные образы. Установите их при наличии Интернета. Пройдите [установку на Mac](MACOS_FULL_DEPLOYMENT_AND_TESTING-RU.md), завершите `durka.py setup`, поднимите стек и проверьте его до выезда.

Сохраните репозиторий, приватный каталог `local/` и Docker data. Перед офлайн-запуском не удаляйте образы, не сбрасывайте Docker Desktop и не запускайте cleanup/prune. Setup может скачивать и собирать; обычный запуск использует подготовленные образы и не должен незаметно делать pull.

<a id="rehearse-without-internet"></a>
## Репетиция без Интернета

<a id="prepare-clean-event-state-after-a-rehearsal"></a>
### Чистое окружение соревнования после репетиции

Не удаляйте подготовленный workspace до создания замены. Сначала остановите native Neo worker (`Ctrl+C`) и выполните `down` с учебным конфигом. Сохраните кеш закреплённых исходников и Docker-образы. На том же подготовленном Mac/Linux:

```bash
python3 durka.py --config local/event.json prepare-clean --from-config local/rehearsal.json
python3 durka.py --config local/event.json prepare-clean --from-config local/rehearsal.json --apply
```

Первая команда — read-only preview. Вторая создаёт **новые** приватный конфиг и `local/event-workspace`, используя проверенные сохранённые образы и локальные закреплённые исходники. Она ничего не скачивает, не собирает, не запускает контейнеры, не копирует прежние базы/задания/захваты и не удаляет репетицию. Создаются новые локальные пароли, placeholders для жюрейки/команд, пустые данные и пустой FILE-захват. Прежние локальные порты сохраняются; начальный bind нового стека — `127.0.0.1`. Отсутствующие образы, грязный/отсутствующий кеш исходников, работающий исходный deployment, удалённый Docker endpoint или существующие выходные пути блокируют подготовку. Частичный кандидат после сбоя сохраняется для проверки; повторяйте с новым именем конфига.

Заполните `local/event.json`: реальный LAN bind, команды, IP Vulnbox, формат флага и согласованные параметры отправки ForcAD. Затем выполните `configure`, `up` и `doctor` с `--config local/event.json`. Worker и отправка включаются отдельно; не включайте их с placeholders. Новый native Neo конфиг — `local/event-workspace/config/neo-native.yml`; используйте подготовленный бинарник, а не прежний учебный клиентский конфиг. После изменения LAN bind передайте Neo переопределение `--host MAC_LAN_IP:NEO_PORT` вместе с новым конфигом. Зависимости каждого скрипта готовятся отдельно.

Проверьте новую установку и запуск без Интернета до удаления учебных конфига/workspace. Сохраните репозиторий, закреплённый кеш исходников, образы, Neo binary и отдельный Linux LIVE bundle. Для фактического разрешённого узла/интерфейса создайте новый LIVE-конфиг: заполненный учебный конфиг непереносим. Это **чистые данные приложений на уже подготовленной машине**, а не офлайн-установщик для пустого Mac. Не используйте Docker prune/reset или широкое удаление `local/`.

Оставьте Ethernet/LAN, но отключите Интернет своим разрешённым способом. Не меняйте сеть соревнования.

```bash
python3 durka.py down
python3 durka.py up
python3 durka.py status
```

Откройте Farm и Packmate, проверьте Neo безвредным скриптом, просканируйте локальную копию сервиса и импортируйте закрытый синтетический PCAP. Остановите и запустите стек снова. Если что-то пытается скачиваться, исправьте подготовку ещё дома. Ручной PCAP-анализ остаётся доступен, когда LIVE-захват запрещён.

Это офлайн-перезапуск подготовленной машины, а не установка на пустую. Экспорт Docker images сам по себе не включает Python, Docker Desktop, локальный конфиг, лицензии или Neo client.

<a id="optional-core-archive"></a>
## Необязательный архив core

Сопровождающий может создать архив только tracked-исходников из закоммиченного checkout. Родительский каталог должен существовать, путь архива должен быть новым.

```bash
python3 scripts/build_offline_bundle.py --output ../offline-kit/durkahelper-core.tar.gz
python3 scripts/build_offline_bundle.py --verify ../offline-kit/durkahelper-core.tar.gz
```

В core-архив не входят ключи, локальные данные, логи и PCAP. Сторонних runtimes/images в нём тоже нет. Проверка автоматическая; для обычной работы переписывать хеш не нужно.

<a id="moving-an-external-cache"></a>
## Перенос внешнего кеша

Для другой машины есть расширенные утилиты export/import: они сохраняют закреплённые образы и проверяют входную inventory. Это не часть обычного запуска.

```bash
python3 scripts/toolchain_inventory.py --help
python3 scripts/toolchain_bundle.py --help
```

Низкоуровневые команды намеренно требуют независимо доверенного входа для импортируемых архивов. Не обходите эту проверку и не выдавайте частичный экспорт образов за полный установочный комплект. Заполненные inventories храните приватно. Перед распространением проверьте [лицензии](../THIRD_PARTY_NOTICES-RU.md); [developer fixtures](../integration/README-RU.md) проверяют изолированный cold start.
