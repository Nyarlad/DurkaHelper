<a id="find-and-fix"></a>

## Найти и исправить

1. Запустите [офлайн-сканер](../offline-scanner-RU.md) на локальной копии сервиса, которую вам разрешено проверять.
2. Откройте ссылку на конкретный раздел для каждой находки.
3. Просмотрите разделы языка и конфигурации, предназначенные только для ручной проверки; их команды rg находят код для анализа, а не подтверждённые уязвимости.
4. Внесите совместимое исправление и проверьте поведение для владельца и другого пользователя, старые данные и checker соревнования. Используйте [проверку патча](../patch-validation-RU.md).

Каждый раздел построен по схеме **Поиск → Уязвимый вариант → Исправление → Проверка**.
Покрытие: **174 автоматических сигнала и 120 разделов только для ручной проверки**.
Две темы, ранее проверявшиеся только вручную, теперь имеют намеренно узкие автоматические сигналы; ручной поиск остаётся необходимым для остальных форм.

Пустой отчёт не доказывает безопасность. Пользовательские wrappers, сгенерированный код, defaults конкретных версий и бизнес-логика требуют ручного анализа. Сканер не импортирует и не исполняет код цели и не обращается к сетевой базе уязвимостей.

<a id="example-boundaries"></a>

## Границы применимости примеров

Функции вроде validateOwnedResource и evaluateAllowedExpression обозначают логику, которую нужно реализовать самостоятельно; это не готовые зависимости. Шаблоны патчей никогда не применяются автоматически. Сохраняйте штатное поведение, границы авторизации, старые данные и совместимость с checker.

Отделяйте данные от кода и аргументов. Массив argv без shell всё ещё допускает опасные опции вызываемой программы; проверяйте собственный контракт утилиты. Парсер или проверка типа не заменяет авторизацию. Корректное исправление может сохранить синтаксический сигнал сканера.

Исторические A/D-примеры сохраняют зафиксированные версии источников и авторство. Проверка семантики исходников не доказывает, что каждый пример запускался на всех поддерживаемых runtime. Каталог не предлагает устанавливать устаревшие версии, упомянутые для объяснения исторического поведения.

См. [покрытие и разработку правил](../development-RU.md): независимые положительные и отрицательные fixtures и заявленные ограничения детекторов.
