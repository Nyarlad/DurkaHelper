# Review своего сервиса

[English](code-review.md) | Русский

Работайте с локальной копией исходников, которую вам разрешено проверять. Используйте [сканер](offline-scanner-RU.md) и [каталог](vulnerabilities/README-RU.md), чтобы найти конкретные места для review.

<a id="identify-startup-and-dependencies"></a>
## Определите запуск и зависимости

Свидетельство: `REVIEWED`; эффект `READ-ONLY`; рабочий каталог — checkout сервиса. Требование: ripgrep. Ожидается: список возможных манифестов без исполнения кода. Пути в выводе могут быть приватными. Rollback: не нужен.

~~~bash
rg --files -g 'Dockerfile*' -g '*compose*' -g '*requirements*' -g '*lock*' \
  -g 'pyproject.toml' -g 'package.json' -g 'composer.json' -g 'go.mod' \
  -g 'pom.xml' -g '*gradle*' -g '*.csproj' -g 'Cargo.toml' -g 'Gemfile' \
  -g 'Makefile' -g 'CMakeLists.txt'
~~~

Проследите entrypoint → процесс → конфигурация → маршруты → данные. Никогда не запускайте неизвестные install hooks или исходники только ради их изучения. Сверьте lockfiles с фактически развёрнутым образом и runtime.

<a id="trace-a-request"></a>
## Проследите запрос

1. Источник ввода: body, URL, cookie, header, сохранённая запись, задача или файл.
2. Проверенный субъект и разрешение на конкретный объект.
3. Разбор, нормализация, сериализация, шаблоны и преобразования типов.
4. Чувствительная операция и её фактические аргументы.
5. Исключения, callbacks, awaits и альтернативные пути к той же операции.

Ручные рецепты rg показывают, с чего начать; отсутствие совпадений не подтверждает безопасность. Сопоставьте обычный собственный запрос с разрешёнными логами/PCAP, затем воспроизведите один инвариант на изолированной копии. У запрещённой операции не должно быть запрещённого побочного эффекта.

После минимального совместимого патча повторите регрессионный тест, обычный пользовательский сценарий и чтение старых записей. Следуйте [процедуре deployment и rollback](patch-validation-RU.md).
