# Packmate: разбор трафика

[English](packmate.md) | Русский

Packmate показывает запросы/ответы и ищет по содержимому потоков. Он помогает защитнику распознать атаку и проверить изменение нужного поведения после патча. DurkaHelper даёт конфигурацию и launch/import; upstream-исходники не меняются.

<a id="ui-services-and-patterns"></a>
## Где настроить сервисы и поиск в UI

Порт веб-интерфейса задаётся при deployment (`--ui-port` для SSH LIVE).
Это **не порт анализируемого приложения**. Интерфейс захвата и IP стороны
сервиса задаются в приватном deployment-конфиге, не в форме создания сервиса.
Шестерёнка справа открывает дополнительные настройки UI.

1. На верхней панели нажмите **+**: заполните **Name** и **Port** приложения.
   Для нескольких портов создайте отдельную запись на каждый. Без регистрации
   сервиса потоки не сохраняются. Для обычного HTTP расшифровка TLS не нужна.
2. Выберите созданный сервис на верхней панели. В LIVE новые потоки появляются
   автоматически; кнопка запуска анализа есть только в FILE.
3. Для подсветки откройте **Patterns → +**. Укажите узнаваемый синтетический
   текст, например `DEMO-`, поиск подстроки, оба направления и действие
   **Highlight**, не **Ignore**. При необходимости выберите конкретный сервис.
4. Откройте новый поток и проверьте запрос и ответ. Новый pattern действует на
   последующие потоки; **Lookback** применяет его к уже сохранённым.
   **Pause** приостанавливает отображение в вашем браузере, не сам захват.

Эти действия изменяют настройки Packmate в его БД, а не приложение или сеть.
Если UI пустой, сначала проверьте регистрацию порта и отсутствие фильтра по
pattern; затем IP стороны сервиса и наличие разрешённого трафика.
Элементы сверены с [upstream UI guide закреплённой версии](https://gitlab.com/packmate/Packmate/-/blob/938031f1dedfbedabef5b049368ed5b6ba6a900a/docs/USAGE_EN.md).

<a id="file-on-the-laptop"></a>
## FILE на ноутбуке

```bash
python3 durka.py up
python3 durka.py traffic import /path/to/closed-capture.pcap
python3 durka.py status
```

Откройте URL Packmate. Логин/пароль — `credentials.packmate_user / packmate_password` из приватного конфига админа.

1. [Зарегистрируйте сервис и шаблон поиска в UI](#ui-services-and-patterns).
2. Проверьте `profile.packmate.local_ip`: это IP стороны сервиса **в capture**, а не адрес ноутбука.
3. В боковой панели один раз нажмите жёлтую кнопку разбора FILE со стрелкой вниз
   и найдите известные запрос/ответ с правильным направлением. Не ищите буквальную
   надпись «Start» или форму загрузки: сам файл уже передан import-командой.
4. Для следующего закрытого файла повторите import; перезапустится только Packmate, БД/предыдущий файл сохранятся.

EOF не сбрасывает started upstream. Не меняйте активный файл вручную под работающим parser. Трафик может содержать пароли, cookies и флаги; не показывайте в публичных artifacts.

Import не меняет `local_ip`: он должен совпадать с реальным IP стороны сервиса
в данном PCAP, а не адресом из другого демопримера. Если конфиг FILE требует
изменения после setup, используйте [процедуру down → edit → configure → up](MACOS_FIRST_RUN-RU.md#6-failures-and-safe-shutdown),
затем повторите import и нажмите кнопку разбора FILE.

<a id="live-on-linux"></a>
## LIVE на Linux

LIVE требует разрешения и точки наблюдения, которая видит пакеты Vulnbox: сам Vulnbox или разрешённый Linux mirror/capture node. Обычный deployment Docker Desktop — только FILE.

Выберите и прогоните [вариант захвата](traffic-capture-RU.md) до игры. Бесконечный FILE pipe не равен LIVE: timeout незавершённых потоков/periodic cleanup привязаны к LIVE upstream. Ноутбук на том же switch не видит весь трафик автоматически.

<a id="resources-and-troubleshooting"></a>
## Ресурсы и диагностика

Текущий образ Packmate только amd64; Apple Silicon использует эмуляцию. Следите за CPU, памятью, ростом БД/capture и диском. Очистка LIVE по возрасту — не жёсткая disk quota; у FILE нет периодической LIVE-очистки.

UI пустой: регистрация сервиса, pattern, IP стороны сервиса, время и известный capture. Направление TCP/UDP и содержимое полезнее статуса работающего контейнера.

Конфиг подавляет конкретный upstream authentication-failure logger, который иначе печатает введённые пароли. Используйте сгенерированную конфигурацию; не запускайте stock-логирование с приватными credentials.
